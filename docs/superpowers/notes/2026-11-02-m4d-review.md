## Fix rounds

### Per task (from the ledger)

- **Task 1** (two reviews). Critical: the walker was quadratic on table cells and `<br>` (8-32 s);
  span text is now built from pieces. `parse5`'s attribute dedupe is quadratic, and the
  attribute pre-scan could be bypassed (comments, raw-text elements, CDATA), so attributes are
  counted exactly in the tokenizer (1,000 per tag). `parse5`'s `_adoptNodes` is quadratic, so the
  tree adapter overrides it with a linear move (identical to stock on 20k inputs; this relies on
  the exact 7.3.0 pin). Links are looked up in a map. Minors: the raw-text elements `noembed`,
  `noframes`, `xmp`, `plaintext` and `title` are removed with their content, a figure holding
  another figure keeps its caption as a paragraph, and images inside `pre` or `figcaption` are
  reported. Timing tests became growth-ratio tests with 5 s caps.
- **Task 2.** Important: the editor reorders span marks on save, so the canonical form sorts them
  (Ruling 2 amended).
- **Task 3.** Approved. Note: `capWarnings` did not bound message length, so producers had to
  (closed by the final review's 1,000-character cap).
- **Task 4.** Important: a required field emptied by the image cap was not reported, and markup
  issues under `"fail"` were unbounded (now 19 plus a summary per field). Minors: a spurious
  `required`, a comment wrap.
- **Task 5.** Critical: a Workers livelock. A dropped failing image was fetched again in every
  batch after a deferral and could spend the budget forever; failed keys are carried in
  `job.deferred` and seeded into `mediaFailed`. Important: the fail error names the URL. Minor: a
  shared URL fails if any field says `"fail"`. The ratio tests were hardened (best of 5, under 10).

Three rounds, all about memory and CPU in a 128 MB Worker isolate. The logs and scripts lived in
the session scratchpad (`fix/peak-final.log`, `fix2/final-mem.log`), which was not kept; the
tables below copy them. The memory figures below were
measured on Node with `--max-old-space-size` (and `--max-semi-space-size=1`), running
`applyTemplate` on one record from a bundle of the engine. **They are Node heap figures at
128 MB, not workerd measurements**: workerd exposes no memory API. The workerd tests show only that
the same worst cases fail cleanly there.

   reference definition used thousands of times rendered tens of megabytes, and three fields at

   stopped at 2 MiB inside `markdown-it`'s own loops; the record's sources limited to 512 KiB

## Rulings

The plan's rulings 1-17 hold as written, with these amendments and additions from the reviews:

- **Ruling 1** (exact nesting in `parse5`) extended: attributes are counted exactly in the
  tokenizer, and the tree adapter also counts created nodes (150,000) and overrides `_adoptNodes`
  with a linear move.
- **Ruling 2** amended: a span's marks are sorted in the canonical form.
- **Ruling 6:** no `invalidImages` on the draft; `PortableTextDraft` is `{ blocks, images }`.
- **Ruling 12** extended: Markdown limited to 128 KiB per field, sources to 512 KiB per record,
  `markdown-it` to 100,000 tokens per field; the JSON budget is enforced while converting, with
  160 bytes per image; when one field passes it, the record's later fields are not converted.
- **Ruling 13** extended: rows hold at most 50 errors (`errors_truncated`), and messages at most
  1,000 characters.
- **Ruling 14:** the budget-deferral test is on workerd, not Node.
- **Ruling 15:** no `source` on `MediaLookup`; a shared URL is looked up by both paths and
  downloaded once.
- **New:** failures of downloads actually tried are carried across deferrals, to the deferred
  record only; field-independent type refusals are cached per batch (M4c fields too); a required
  field left empty after downloads fails `required`.

The spec is brought in line with these in the same commit.

## Open issues for the next part

- **A persistently failing image re-plans `update`.** With `imageErrors: "drop"`, a dropped image
  is a pending change on every run (Ruling 17), so the record plans `update` each time. A plain
  re-run then writes the same value and plans `unchanged` (Task 7 pins this), but when the entry
  has a pending draft or a lock it reports `conflict` or `locked` on every run.
- **Refresh on a shared URL** converges after one extra update.
- **A field-dependent type refusal** (a type only this field refuses) is fetched once per record,
  not once per batch; field-independent ones are cached per batch.
- **The open-block estimate leaves out link definitions.** The running JSON budget counts an open
  block's text and spans, not its `markDefs`; the exact size check after conversion is the
  backstop, so a field can build somewhat past the budget before it fails.
- **Later fields' warnings are lost** when one field passes the record's JSON budget: the later
  fields are not converted, so the row has the error but not their warnings.
- **No integration test for the `text` format or the editor round trip.** They are covered by unit
  tests and V2 (and manual check 3).
- **Known flakes.**
  - F1: the WSL clock steps back about 5.4 s while integration servers restart; `crash.test.ts`
    and M4c's slow-download deferral test can fail. Neither did in either run.
  - F2: the one-off workerd `500 INTERNAL_ERROR` "Plugin route error" from Task 8's drafting run
    did not recur in Task 8, the two final-review `test:cf` runs or the coordinator's run at
    `1d1ab92`. Still unexplained.
  - `url-sources.test.ts` sometimes finds port 4395 "in use" after `media.test.ts` (M4c note).
    It did not happen in either run. A related cause seen in this run: a Windows process
    (`Cursor.exe`) listening on `127.0.0.1:4397` blocks `retention.test.ts` through mirrored
    networking, invisible to Linux tools. A port-in-use failure is worth checking with
    `netstat.exe -ano` before treating it as a race.
- **Known gaps from the spec and plan.** Tables, embeds, galleries, `htmlBlock` passthrough,
