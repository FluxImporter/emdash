### Final branch review

Fixes in `b595825`, `660967e`, `380b5ce`, `943d320` and the spec in `cfce216`, then one more fix
(`b3c8c4b`) after a re-check:

1. **The media warning** is built from one `journalMedia` query (at most 100 IDs in `seq` order,
   "more than 100 … and more"), so it no longer depends on a batch having saved the summary; the
   summary keeps only terms (`created: { terms, termCount }`).
2. **Retention and a rollback in flight.** Retention marks a job `purging` (compare-and-set)
   before it deletes any row; `jobs/rollback` refuses a purging job, and a rollback whose original
   is gone or purging fails `rollback_original_gone` instead of completing with no rows. `b3c8c4b`
   moved that check into the rollback's own batches.
3. **Rolling back a `publish: false` job published an earlier draft.** The pre-image held only the
   fields the job changed, so step 2's publish made the rest of the importer's earlier pending
   draft live. Every field of a pending draft whose draft and live values differ is now
   journalled, whether or not the job publishes (Node test added).
4. **I2, a resumed write that found the entry moved.** The pre-image is marked `uncertain` and the
   rollback refuses it (`rollback_changed`), deliberately also when the stopped write itself had
   landed. `b3c8c4b` (N7) stopped the spurious flag when the job's own link names the entry's
   revision.
5. **I3, term edits do not move `_rev`.** The journal keeps the term groups each write gave
   (`wrote.taxonomies`); the rollback reads the entry's terms (one read, `COST_READ`) and refuses
   an entry whose terms changed since.
6. **An entry moved to Trash by someone else** after the import created it is `rollback_changed`
   and never deleted for good.
7. **Unjournalled draft edits.** A resumed step is adopted only when no draft difference outside
   the journal is left; `b3c8c4b` (N1) applies the check from step 1 on (it started at step 2).
8. **An unchanged verdict** holds only while the link row is the one the pre-image read, so a
   row refused because a later job's link names the entry stays retryable after that job is
   rolled back.
9. **I5, references to deleted entries.** A rollback that deletes for good warns once on the job:
   "Deleting an entry also removes references other entries hold to it." (EmDash has no
   backlinks API.)
10. **The Workers budget.** Revert steps, Trash and delete are charged to the lookup budget,
    references the entry still holds are not looked up, and `b3c8c4b` reserves a row's worst case
    (`ROW_RESERVE` 135 plus `COST_READ` per reference ID) before each row after the first.
11. **Clean-ups** (`660967e`): `purging` moved into `Job`, `CHANGED_MESSAGE` no longer exported.

## Rulings

The plan's Rulings 1-13 hold as written, with these amendments from the reviews (each recorded in
the spec):

- **Ruling 2** (Workers cap): the rollback cap stays 3 (V7). The import caps it asked this task to
  re-measure were lowered: `WORKERS_LINKED_BATCH_CAP` 10 → 6 and `WORKERS_BATCH_CAP` 20 → 11 (V8).
- **Ruling 5** (ownership): a linked create is owned by revision only; the timestamp rule applies
  only when no link row names the entry with a `writtenRev`; such an entry is only trashed. An
  `update` row is `unchanged` only while its link row equals `before.link`. New refusals before
  step 1: `uncertain` pre-images, changed terms, an entry trashed by someone else.
- **Ruling 6** (rollback job): the warnings now read media from `journalMedia` and terms from
  `created`; a third job warning names the references a permanent delete removes; a purging
  original is refused.
- **Ruling 8** (record rows): rows also save `pendingStep`, and once more after the last step
  before the link moves.
- **Ruling 9** (retention): `purging` before deletion; an original held by any rollback job is
  pruned together with it once both have expired, whatever the rollback's status.
- **New codes**: `required` (Task 6, the import's own code for a pre-image value empty in a
  required field), `references_not_restored`, `ambiguous_source_id` (the M4e lookup error), and
  `rollback_original_gone` (job error).

## Deviations from the plan

- **Caps lowered** (`0c58020`), as Step 2 directs: both import caps, not the rollback cap. The
  brief's formula (largest batch divided by its rows) gave 13 for the unlinked cap, which still ran
  978 queries because of a fixed cost of about 240 per batch; 11 was measured at 864. No test named
  a literal value (they import the constants), so no test changed. The M4c, M4d and M4e specs
  still quote the old values as history.
- **More measurement than the brief listed:** the coordinator's unlinked batch at
  `WORKERS_BATCH_CAP` with publish and the journal on; `journal: false` baselines; a plain-update
  rollback; a rollback restoring 15 references per row; and the lookup units each batch spent,
  through a temporary global set in `src/engine/batch.ts` (also reverted). The worst-case rollback
  used scheduled drafts so that one row runs five steps.
- **Manual checks.** The REST API stood in for the admin screens (no browser), as in M4d and M4e.
  Check 4's resume refusal needed a failed original, since completed and cancelled jobs are never
  resumable. The checks ran while the last fix was being written in the same checkout (see Manual
  checks).
- **Order of runs.** A first `pnpm test:integration` started before the last fix was stopped, so
  the full suites ran on the final code: the probe, then `pnpm test:cf`, then
  `pnpm test:integration`.
- **Spec drift fixed in the docs commit:** the job fields `created` and `purging`, the record
  fields `pendingStep` and `writtenRev`, `before.referencesUnknown` in the journal interface, the
  `rollback_original_gone` code, the `uncertain` exception for the job's own link and the step 1
  start of the unjournalled-draft check (both from `b3c8c4b`), the budget reserve, and the
  measured V7 and V8 numbers.

## Open issues for the next part

- **Known gaps of the design (coordinator list).**
  - **References staged in a draft.** `handleContentGet` returns a pending draft's reference
    selection, not the live one, so a publishing job that writes over a published entry with a
    pending draft records `referencesUnknown`; its rollback leaves the references as the draft had
    them and warns `references_not_restored` on the `reverted` row.
  - **The staged slug (F5).** A staged slug in a pending draft is not returned, so it is not in the
    pre-image: rollback restores the live slug, and rolling back a later job leaves an earlier
    pending draft without its slug.
  - **Media and terms are not deleted** (F13, F14). The rollback lists them (at most 100 media IDs,
    then a count; terms by number, named under `newTerms`). The media map rows stay, so a re-import
    reuses those items. A crash between a media upload and its `journalMedia` put leaves the item
    off the list.
  - **`publishedAt` is kept** (F12) on an entry the run published for the first time, and its
    publish hooks run once more (Ruling 1).
- **A single row can exceed the Workers limit only in extreme cases.** The worst measured revert
  row was about 250 queries; a row restoring 15 references about 180. The reserve stops a batch
  before a second row that would not fit the budget, but the first row always runs, and a pre-image
  restoring hundreds of references (each one lookup) could exceed 1,000 queries on its own. Not
  measured; the import's own `journal_incomplete` truncation check bounds a selection at one page.
- **The import caps were over the limit before M5a** (V8), on the paid plan's 1,000 queries; they
  are now 11 and 6. Local workerd does not enforce the limit, so only a deployed Worker would have
  failed. A template with many more links per record than the measured one (three references, two
  taxonomies, two bylines) could still exceed it at 6; the lookup budget is what bounds that, and
  it was never the binding limit in these measurements.
- **The lookup budget's rate.** The spec costs a read at 2.2 queries per unit; measured, reference
  lookups ran about 1, revert steps up to 1.5. 600 units stay at about 920 queries at most.
- **From the spec's open issues** (each documented there): references a permanent delete removes
  from other entries (job warning); Trash and permanent delete take no actor; an orphaned rollback
  job after a stop between its create and the `rolledBackBy` compare-and-set; the fakes' standing
  clock (timestamp rules also run under a moving one); three storage calls per create for the
  journal; jobs created before M5a have no `sourceId`, so cancelling them does not clear
  `lastImport`; on a collection without revisions a resumed row stopped after step 3 can report
  `rollback_changed` where nobody edited (F18, safe); the `required` check treats only `null` and
  missing as empty, as EmDash does; an `update` row whose job never wrote can pass as `unchanged`
  when its link save was lost and an editor then staged a draft (nothing destroyed); rollbacks must
  go newest first and translation jobs before their source; a step that fails after a partial write
  on D1 leaves the entry `rollback_changed`; the rollback window is the retention period;
  `lastImport` is still set at creation, so a running or paused job makes the same content skip.
- **From the ledger.**
  - A crash after the `writing` save and before the update, with an editor's change in between,
    keeps the first pre-image (Task 4 note): the editor's change is then treated as the pre-run
    state only if the resumed write marks it `uncertain` (final review I2), which the rollback
    refuses.
  - The term summary is lost for a batch that crashes after creating terms and before its save, so
    the kept-terms warning can undercount (Task 5 note); the media warning no longer depends on it.
  - Four equivalent mutants survive in the rollback pass (Task 6).
  - The `uncertain` refusal is deliberately conservative: it also refuses a row whose own stopped
    write had landed.
- **Settled by M5a.** M4c's "M5 rollback needs its own record of job-created media"
  (`journalMedia`); the `lastImport` skip after a cancelled run; M4e's partial linked creates on D1
