## Deviations from the plan

- **Date format IDs (spec wording).** Built-in formats 14-22, 45 and 47 are dates; 46 is `[h]:mm:ss`, an elapsed time, and stays a number (ECMA-376 §18.8.30). The spec said otherwise and was corrected.
- **Task 4 fix round (preflight P1, P4).** The plan's code threw `RangeError` on a huge date serial and read a shared-string cell without `<v>` (or with `<v/>`) as string 0 or unreadable. Both were fixed after review: a huge serial is an unreadable cell and is counted, and such a cell is `null` and not counted. Rows whose cells are all unreadable are skipped with their own warning rather than silently. Commits 274b5f0 and 55092c5 (on the branch as 13497dd and 01ae6b9).
- **Sources and limits (preflight P2).** `sources/fetch` knows no template and keeps the general `maxSourceBytes` limit; `jobs/create { sourceId }` with an XLSX template enforces the 10 MiB limit (fetch cap and check before conversion). The spec wording was updated. Cost: a large non-workbook download can happen before conversion refuses it.
- **Structural sheet problems (preflight P3).** A cell past XFD, a row past 1,048,576, rows out of order and an unparseable `<row>` fail the whole conversion, as the plan rules; the spec now separates structural problems from per-cell value problems. One malformed row rejects the file.
- **Invariant error (Task 5).** `createJob` throws a plain `Error` (a 500) when an XLSX template reaches it without columns. Every creation path passes columns, so it can only fire on a programming error.
- **Task order.** Tasks ran in parallel waves (1 and 3, then 2, 4, 5, then 6 and 7, then 8) on worktrees and were cherry-picked onto the branch. Task 6's review, this task and the final whole-branch review ran in parallel, so this note's commit is outside the final review's range.
- **Brief commands.** The brief's vitest command finds no files from the repo root; vitest was run from `packages/flux-import`.

## Open issues for the next part

- **Workers memory in the worst case.** The workbook is read whole (at most 10 MiB) and its shared strings are held as one array (up to 50 MiB of text, about twice that as JavaScript strings); with the converted-lines buffer (at most 32 MiB) the worst case for a 10 MiB workbook with large shared strings is close to the 128 MB isolate (Task 5 review). Only small workbooks were run on workerd, so the limit is unmeasured. XLSX on a deployed Worker is also unverified beyond local workerd, because the production Cloudflare build blocker from M2 still stands.
- **CJK built-in date formats are not detected.** Excel's locale-specific built-in IDs 27-36 and 50-58 (Japanese, Chinese, Korean) are read as numbers, not dates.
- **Sheet scan CPU is bounded only by the 100 MiB part cap** (preflight P5). A pathological sheet of empty cells can make a conversion slow, notably on Workers.
- **One sheet per job; formulas are not evaluated** (a formula without a cached value is `null`); `.xls`, `.xlsb`, `.ods` and `.xlsm` stay refused.
- **Known WSL flake.** `crash.test.ts` can fail when the clock steps back during a server restart (M3c Fact F1); it did not in this run.
- **Minor, deferred from the task reviews:**
  - Zip (Task 1): on workerd an oversized declared `compressedSize` fails closed with a trailing-bytes error where Node ignores the extra bytes; some defensive branches are untested (patched directory offset, local header bounds, data descriptor, entry count mismatch); trailing bytes after the archive are refused with "truncated" wording; an empty 0-byte deflate entry is refused; names are always read as UTF-8.
  - Workbook (Task 2): a workbook with no relationships part reports "no worksheets"; tests are missing for `../` inside the archive, no rels part and the shared strings `maxBytes`; `_xHHHH_` escapes split across runs are not decoded; whitespace `#text` on `<c>`/`<row>` with `keepBlankText` must not be read.
  - Cells (Task 4): empty strings count as values for the empty-row check; a `lines` iterator never consumed leaves its generator open; `AAAA1` is placed after the previous cell; a whitespace-only `<v>` on `t="s"` maps to shared string 0; the comment at `xlsx.ts:31` omits the skipped-rows counter.
  - Routes (Tasks 3, 5, 7): `sources/paste` refuses XLSX before the user check (400 before 401); the sourceId unit test rebuilds route wiring by hand (the integration test covers the route); the full conversion runs before the cheap template validation; the TOO_LARGE test does not assert that nothing was staged; the length-declared R2 copy is inferred, not asserted; the workerd test checks only `SKU-0`.
  - Preflight: the zip-bomb test checks only the message; the merged-cell test cannot fail (no merge handling is needed); the zod fragments, the two `textOf` helpers and the four `failure()` helpers are duplicated.
  - Storage: staged workbooks keep a `.csv` suffix in `sites/dev/uploads` (`flux-import-upload-<id>.csv`), whatever their format; this is cosmetic.
