**What a read costs.** A count batch of 40 reads ran 131 queries, about 2.4 a read beyond the batch's

and binds early. That fails safe: batches are smaller than they could be. The act stage's worst

spec's 70.

## Open issues for the next part

- **Template documentation for M6** (plan Ruling 7). The text of the `rules.owner` doc comment in
  `src/engine/template.ts`, for M6's template reference:

  > `owner` (M5c) names the entries this template's jobs create; `missing` needs it. One owner
  > name, one feed: two templates with the same owner, collection and locale act as one import,
  > each one's missing phase treating the other's entries as its own. The phase refuses when it
  > can tell that two URL sources share the owner; it cannot tell for uploads and pastes. With the
  > default `maxPercent` of 25, an owner with fewer than four entries refuses as soon as one is
  > missing (1 of 3 is 34%), and one with four accepts one. Feeds whose items come back should use
  > `unpublish`: a trashed entry whose key returns stays a `missing_trashed` conflict until it is
  > restored. A refused run is re-run with the job option `missing: { maxPercent }`, for an
  > unchanged URL source also with `force: true`.
- **Clock skew across processes can order job IDs wrongly** (plan Ruling 1). Within one process,
  same-millisecond IDs count as later (fail safe); across processes with skewed clocks, a later
  job's link can look earlier.
- **A rolled-back swept entry reads as edited to the next phase** (plan Ruling 13). Its `_rev` moved
  past the link's `writtenRev`, so it is `missing_edited` until the import writes it again.
- **Versions.** `package.json` stays 0.1.0 while `FLUX_IMPORT_VERSION` is 0.2.0. The storage docs
  ask for a version bump when an index changes, and M5c adds `["owner", "collection", "locale"]`
  to `links`. The constraints forbade touching `package.json` in M5c, so the two are to be aligned at
  release (M8). That is harmless for a native plugin, whose descriptor reads `FLUX_IMPORT_VERSION`.
- **The read charge is conservative.** `COST_MISSING_READ` (12) is several times a measured D1 read
  (about 2-3 queries, also on the linked collection), and the spec's "about 12 D1 queries" for a
  `content.get` is a projection the counts did not bear out. The worst batch used 436 of the 1,000
  queries, so the caps could be raised. Doing so would need the worst case measured again, with
  wider records.
- **Act-stage paging** (ledger). An act page holds at most 10 links on Workers, so a large healthy
  feed spends one act batch per 200 seen links: 43 act batches of 45 queries before the first
  decision on the 8,800-link feed. The count stage takes 800 links a batch.
- **From the spec's open issues** (each documented there):
  - trash takes no `_rev`;
  - term and reference edits elsewhere move no `_rev`;
  - a synced translation reads as edited;
  - a hand-restored entry is `pending_draft` until published;
  - a trashed key that returns stays `missing_trashed`;
