## Deviations from the plan

- **Task 0 skipped.** The plan agent proved V1-V3 on Node and workerd (see above).
- **Tasks 4 and 6 merged** into one implementation, and several commits were cherry-picked from
  task worktrees (Tasks 2, 3, 4+6, 5, 8).
- **Self-referencing `key` on a first import (Task 3 ruling, spec updated in `300d324`).** A
  `match: "key"` reference into the job's own collection skips the "`flux_source_id` must exist"
  check, because the job adds that field on its first real batch.
- **Plan wording (`300d324`).** The byline page cursor is `cursor`, not `nextCursor`.
- **Fix rounds beyond the plan's code.**
  - Task 1: linear-time dedupe; flat-term messages.
  - Task 2: malformed `findEntry` responses become `bad_response`.
  - Task 3: no double read of fields.
  - Task 4+6: more than 50 selections are marked `referencesTruncated` and always plan changed.
  - Task 5: a slug that would be created under two parents is refused (`term_path_mismatch`) before
    anything is created; planned dedupe; stop after a failed create; skip the index on empty.
  - Task 7: a dry run's planned terms are kept on the job (`plannedTerms`, capped at 5,000 and
    256 KiB, with a warning); planned keys are looked up through a `[jobId, sourceKey]` records
    index; a retried row keeps its `newTerms`.
- **Final whole-branch review (`4c88a1c`, `bc3a6e5`, `a054251`).**
  - A dry run looks up `flux_source_id` only when the collection already has it
    (`sourceIdReady`, with `sourceIdField` stored on the job).
  - Linked batches on Workers carry a lookup cost budget: 600 per `jobs/next`, with a call costing
    1, a read 5, a term creation 6 and each record 25. This bounds D1 queries beyond the plan's
    10-record cap.
  - Planned keys are bounded to the import pass and must come from an earlier row.
  - Planned terms are hidden from job status, bounded in size, and kept until a retry ends.
  - The spec now states that a dry run cannot foresee `id` or `slug` references to entries the
    same job creates.
- **Brief expectation for manual check 1.** The brief expected all three rows `planned`. Under the
  final-review ruling above, the two rows with slug references to posts in the same file report
  `reference_not_found` in a dry run (see manual check 1).
- **Brief commands.** `pnpm test` was run as `pnpm exec vitest run` in `packages/flux-import`
  (the same script). The manual checks used the REST API rather than the admin screens.

## Open issues for the next part

- **Known gaps from the plan (all in the spec).**
  - A mapped taxonomy replaces the entry's terms of that taxonomy. An additive mode waits for M5's
    "update only these fields".
  - Terms and bylines are looked up in the template's locale only, and term translations are not
    linked (M4e).
  - A `key` reference to an entry the job writes later fails until `jobs/retry` or a second run.
  - A dry run cannot foresee `id` or `slug` references to entries the same job creates (manual
    check 1).
  - Two jobs creating the same label at the same time in `label` mode can make two terms.
  - Bylines are never created, and role labels never come from the source.
  - More than 50 references per field, and unbound (legacy) reference fields, are refused.
  - On revisioned collections, taxonomies and bylines are written live even when `publish: false`
    stages the data (EmDash behaviour).
- **Deferred from the task and final reviews.**
  - The slug suffix on a `label`-mode placeholder term is cosmetic (final review).
  - The `[jobId, sourceKey]` records index is built only on the cron tick (final review).
  - The Workers budget does not cap `createTerm` per record separately (final review).
  - There is no slim `jobs/list` view. Jobs carry `plannedTerms` and `targetFields` (final
    review).
  - The lookup cost weights (`COST_*`, budget 600) were not measured against real D1 query counts
    (final review).
  - A dry run cannot be retried, because `transitionJob` blocks it (final review).
  - A dry run's `plannedTerms` are lost if a dry-run batch crashes before it is released, and
    were visible in job status until the final fix hid them (Task 7).
- **Log CSV.** It has one `error_code` column per record, so a second lookup error code shows only
  in the joined message (manual check 4). This pre-dates M4b.
- **Known WSL flake.** `crash.test.ts` can fail when the clock steps back during a server restart
  (M3c Fact F1). It did not in this run.
- M4c (media) and M4d (Portable Text) build on the same `LookupPort` / resolver split for objects
  outside the entry. The M2-M4a open issues (`2026-10-08-m2-review.md` through
  `2026-10-27-m4a-review.md`) are unchanged by this milestone, and the production Cloudflare build
  blocker from M2 still stands.
