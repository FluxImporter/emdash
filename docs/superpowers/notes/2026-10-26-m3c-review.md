## Deviations from the plan

- `jobs/create` with `sourceId` skips against `lastImport` (the last real import), not against the last fetch (controller ruling). A dry run or a failed job creation therefore never consumes a change; `lastImport` is cleared when the URL or credential changes.
- Tasks 1 and 3 ran in parallel in separate worktrees (from 7e1d97c, reset to f731ba5) and were cherry-picked onto the branch; Task 3 defined a local `Credential` type that Task 2 later replaced with the import from `fetcher.ts`.
- Task 2 fix round: a mid-body error that a wrapping storage adapter turns into `EmDashStorageError` is recorded and rethrown as `FETCH_FAILED` (the plan's code gave a 500 and no `lastError`); a `304` counts as unchanged only after a conditional header was actually sent; Workers buffering streams the buffered chunks instead of copying through a Blob; invalid stored credential entries read as absent and header-set errors carry a fixed message, so no credential value can reach a message.
- Task 4 fix round: `updateSource` and `deleteSource` use `getVersioned`/`compareAndSet` with retries like `saveFetchResult` (the plan used plain puts, which let a rename race a fetch and drop `lastFetch`); errors from recording `lastImport` after job creation are swallowed (best effort).
- Worktrees had to live outside the repo, because Biome finds nested `biome.json` files under `.claude/worktrees` and lint fails.
- Manual check 1: the admin settings route lists `credentials` as a declared secret, so an administrator can overwrite it with other text (plan fact S3); the field description says saving other text removes every credential.

## Open issues for the next part

- DNS can change between the check and the connection (DNS rebinding on Node; accepted, as in EmDash core). Pinning through an undici `Agent` `connect.lookup` would close it. On Workers, Cloudflare's network refuses private ranges itself.
- Two concurrent `sources/create` calls can give two sources one name (plugin storage has no unique index).
- A hostname with a trailing dot is resolved without it but `url.href` keeps it; `http://./` gives an error message with an empty host; IPv4-compatible `::/96` with a public IPv4 is allowed (not a bypass); the abort listener in `guardedFetch` is never removed (harmless with per-request signals).
- Fetcher: a wrong declared `Content-Length` on Workers surfaces as a storage error; the 120 s total timeout bounds body reads only; a staged copy can leak if `exists` or `delete` throws in the hash-unchanged branch; Node's `LocalStorage` buffers the whole stream (pre-existing).
- Credentials: an invalid credential entered through the admin settings page silently vanishes from the list and on the next write (a fetch then shows `CREDENTIAL_MISSING`); `deleteCredential` writes before the 404 check.
- Sources: a job can be pointed at a file that a concurrent changed fetch has just deleted (a visible failure, small window); there is no conditional delete, so a fetch saving between the read and the delete in `deleteSource` leaves an unnamed file (retention purges it); `recordImport` failures are not logged; each retention release scans all sources.
- Tests: `url-sources.test.ts` has a hard-coded port 4395, leaves the feed server listening if `beforeAll` fails, does not assert on disk that the `304` re-run keeps the staged file, and has no integration test of a mid-body `FETCH_FAILED`. Some tests use 20 to 60 ms real timers and may flake. `crash.test.ts` can still fail on this WSL2 machine when the clock steps back during a server restart (plan fact F1); it did not in this run.
- The production Cloudflare build blocker from M2 still stands, so URL sources on a deployed Worker stay unverified (workerd was only exercised locally through `test:cf`).
- Minor duplications ledgered by the preflight scan: a `failure()` test helper, `isRecord` twice, two near-identical blocks in `sources.ts`.
