## Deviations from the plan

Each line is a controller ruling or accepted departure from the M3a spec or plan, with its cost if wrong.

1. Plan rulings from pre-flight: `readerFor(source, columns)` signature; a misplaced `records` is caught by `checkSource`; the paste limit and sample cap are the plan's values; finished jobs delete their staged file, so a re-import needs a re-upload. Cost: a re-import after completion costs an extra upload.
2. The ASCII encoding declaration is accepted (`US-ASCII` and `ASCII`, case-insensitive) as well as UTF-8 (spec: UTF-8 only; Task 5 ruling). Cost: none, ASCII is a subset of UTF-8.
3. XML scanning continues after the root element closes (only whitespace, comments and processing instructions allowed; anything else is `source_syntax`), against the plan's "bytes after the root are not read" (Task 5). Cost: a file with trailing junk fails the job after all its records were imported.
4. A `<` inside an XML tag name is `source_syntax` (Task 5). Cost: none expected.
5. A DOCTYPE longer than the 1,024-byte buffer is rejected with `xml_dtd_not_allowed`, closing a padding bypass of the external-ID check (Task 5). Cost: none, DTDs are never needed.
6. XML CDATA before the root or after it closes is `source_syntax`; blank-text detection uses XML whitespace only (so U+00A0 text is kept); element names must be valid XML names (invalid in a record gives `invalid_record`, as a structural element `source_syntax`) (Task 5). Cost: none.
7. `collectPaths` is capped at depth 32 and 1,000 distinct paths; past a cap the container is listed as a leaf (Task 3; the plan left it unbounded). Cost: very deep or wide feeds show fewer suggested paths in the mapper.
8. A JSON scalar also ends at `"`, `[`, `{` and `:`, so malformed input such as `[abc"]", 2]` fails with `source_syntax` instead of silently dropping records (Task 4). Cost: none, it fails loudly instead of losing data.
9. A CSV retry that finds no record at its saved offset keeps the job code `csv_syntax`; other formats use `source_syntax` (ruling C19, spec: CSV keeps `csv_syntax`). Cost: none.
10. Test-strength rulings D1 (stream cancel test must assert no unhandled rejection), D2 (Task 7 structural-error test also runs the job to `failed` with `source_syntax`) and D3 (Task 9 warnings test creates its own collection), plus shared reader helpers in one module instead of copies in each reader. Cost: none.
11. Task 10: the full `pnpm test:cf` was not re-run; the new JSON and paste parity test and the short upload and lock parity tests ran instead. Cost: a regression in the unchanged 10k workerd path would go unnoticed until the next full run.

## Open issues for the next part

M2 issues, still open and unchanged by M3a (`docs/superpowers/notes/2026-10-08-m2-review.md`):

1. **Production Cloudflare build crashes on start (upstream blocker).** The built worker fails at module load with `Class extends value undefined is not a constructor or null` in `dist/server/chunks/kysely_*.mjs`: the bundler splits kysely into two chunks that import each other (EmDash 1.2.0 + `@astrojs/cloudflare` 14.3.4). It blocks any Cloudflare deployment; the scheduled handler and retention task on a build stay unverified. To be filed upstream by the user.
2. **workerd throughput and the D1 query limit.** 10,000 rows take 872 s on workerd against 55 s on Node (about 9 sequential storage or D1 calls per record), and this applies to every format alike. Local workerd does not enforce Cloudflare's per-invocation D1 query limit (1,000 paid, 50 free), so `pnpm test:cf` cannot catch an overrun; `WORKERS_BATCH_CAP` (20 records per `jobs/next` on Workers) is the only mitigation. Follow-up: measure real queries per record and set the cap from that.
3. The other M2 items (cross-job duplicate window, `kysely` and `@emdash-cms/auth` as peer dependencies, M7 log download with `fetch` and the CSRF header) are unchanged. `stagePaste` reuses `stageUpload`, whose early-failure clean-up gap does not arise for an in-memory body.

M3a deferred minors, grouped (from the ledger):

- Readers: `read()` doc says offset 0 locates the first record (not true for CSV); `takeSample` with `n <= 0` returns one record; no early-return cancel test for `takeSample` and `sampleByRead`; two early-exit `body.cancel()` calls bypass `deferCancel`; fixed sleeps in a test; `drain()` duplicated in `JsonScanner` and `LineScanner`.
- JSON: a scalar record of exactly the maximum size is rejected (the count includes the terminator); `ValueExtent.closers` is unbounded while skipping and its doc comment is stale; `finish` emits a scalar and then throws, so the record is dropped before the job fails; no test for `:` after a scalar.
- XML: the declaration is checked in the first 1,024 bytes only; UTF-16LE without a BOM gives a garbled `invalid_source`; an end-tag name outside a record is unbounded; `&#xFFFE;` and `&#xFFFF;` are accepted; `&#99999999;` is reported as an unknown entity; `paths.ts` has a second, more permissive `XML_NAME` constant (drift risk); U+203F and U+2040 are not allowed in names; `isSpace` reuses the `isJsonSpace` name.
- Paths: an empty JSON key yields an unaddressable path; a bare `#text` passes `pathProblem`; no tests for `__proto__` and `constructor` on JSON or XML, for `/a a/ .a`, or for mixed separators.
- Conversion and engine: a non-finite JSON number into a number field is untested; JSON integers such as 2026 and 20260301 parse as ISO dates in date fields (per ruling); no engine-level successful retry test for XML or JSONL; the job reader is rebuilt per row on retry; the warning wording counts only good sampled records.
- Upload and paste: no exactly-1-MiB multibyte paste test; real pastes hit `INVALID_PLUGIN_REQUEST` 413 before the service `TOO_LARGE`, so two 413 codes exist; no `x.csv.exe`, backslash or NUL upload-name tests; no paste BOM or CRLF test; the paste `format` is validated and then discarded (ruled).
- Tests: format tests check SKU-0 values only; the warnings integration test uses a dry run; the paste test does not compare contents or sha256; XML attribute-on-element paths are only sampled; in the workerd parity test a `template` variable shadows an imported helper and a paste comment overstates what is asserted.
