## Deviations from the plan

- Task 1: the crash-repair lookup is widened to any earlier row of the job (user-confirmed fix for the duplicate-on-retry bug); the writtenRev proof is tied to the entry id.
- Task 1/5: `source_id_field_invalid` from `ensureSourceIdField` is a job-level failure like `collection_missing`, not `internal` after three tries.
- Task 4/5: the `errorCode()`/`schemaErrorCode()` helper is exported once and imported, not duplicated.
- Task 6: `authorId: actor.id` is passed on create only (the plan left created entries without an author).
- Task 7/8: retention-test fixes: the "live lease" test advances the clock so the lease check is what keeps the job; the "does not throw when deleting fails" test is retitled to match its assertion.
- Task 8: retention keeps the uploads of every job that survives the run (`purgeBefore` skips referenced upload ids); upload age decides only for unreferenced files.
- Task 9: routes import `z` from `astro/zod` (EmDash route input is typed against Astro's zod 4.6.5; the workspace pins 4.5.4), so two zod copies are in the bundle.
- Task 12: empty uploads are rejected with 400 `EMPTY_BODY` (declared length 0 or staged size 0, staged file deleted); the plan allowed a 0-byte upload.
- Task 12: the second user for lock tests is inserted through the DB (approved with the plan; passkey-only invites).
- Task 13: the kill-and-resume test is timing-based but asserts the kill landed mid-job and that nothing is duplicated, left `writing`, or miscounted after resume; the retention test uses `retentionDays: 1` with backdated timestamps instead of 0.
- Task 14: workerd `testTimeout` raised from 900 s to 1800 s (the 10,000-row test takes 872 s); the production-build check (Step 6) failed for the reason in Open issues.
- Plan-wide: source layout is `src/emdash/` + `src/plugin/` instead of the spec's `src/writer/`; capabilities `content:read`, `content:write`, `content:publish` and `schema:read` are declared although writes go through the trusted runtime (honest disclosure on the plugins page; justification goes in the M8 README).

## Open issues for the next milestone

1. **Production Cloudflare build crashes on start (upstream blocker).** The built worker fails at module load with `Class extends value undefined is not a constructor or null` in `dist/server/chunks/kysely_*.mjs`: the bundler splits kysely 0.29.6 into two chunks (`kysely_Brmqp8Ih.mjs` and `dist_B06WNNyf.mjs`) that import each other. Reproduced without the plugin (`plugins: []`, no `fluxImportRoutes()`), on EmDash 1.2.0 + `@astrojs/cloudflare` 14.3.4. It blocks any Cloudflare deployment, and the scheduled handler and the retention task on a build remain unverified. To be filed upstream by the user. A `rolldownOptions` chunking workaround was not tried.
2. **workerd throughput.** 10,000 rows take 872 s on workerd against 57 s on Node, about 9 sequential storage/D1 calls per record. Follow-up: merge the `writing` and final record writes, cut link reads. `pnpm test:cf` takes about 15 minutes and is not for routine CI.
3. **Deferred minors worth carrying**, grouped:
   - Crash and retry: a failed row from a throwing repair drops `writtenRev`/`action`/`entryId` (degrades to `publish_unverified`); the dry-run retry lookup writes a link; the repair lookup is scoped to one job, so a crashed and cancelled job A followed by job B on the same file can duplicate (document it).
   - Retention: `deleteRecords` can loop forever if `deleteMany` returns 0 for a non-empty page; one failing job aborts the whole run; a narrow race between `releaseUploadIfUnused` and job creation.
   - Uploads and routes: `stageUpload` does not cancel the body or release the counter on early failures; an unexpected storage error returns Astro's default 500 instead of the JSON envelope; a negative declared `Content-Length` is passed through; the cap boundary is off by one against the brief wording; `jobLogCsv` builds the whole CSV before the size check; `EmDashUploads.open` with a negative offset reads the whole file; `ensureRetentionScheduled` runs before `withServices` on `jobs/create`; no Zod ranges for `batchSize`/`budgetMs`.
   - Schema and conflicts: an existing `flux_source_id` with `translatable: true` is accepted silently; a non-rev unique-constraint conflict on update maps to a revision conflict; rows failing mapping are logged with an empty `source_key` even when the key column is readable.
   - Tests: lock tests in unit suites are compile-only (the integration suite covers real locks); several tests are timing-dependent (concurrent drivers, kill-and-resume); parity tests do not assert the runtime is workerd; the scale tests do not assert `unchanged`/`failed` are 0; missing upload-id rejection cases and a few other edge cases listed in the ledger.
   - Housekeeping: two zod copies (consider aligning the pin with Astro's); an orphan `emdash@1.2.0` (@astrojs/react 7) directory in `node_modules/.pnpm` that a clean install removes; the `@cloudflare/vite-plugin` dev adapter auto-enables `SESSION`/`IMAGES` bindings that a deployment must declare or disable.
