## Regular expressions and single-step work

Regex literals are rejected at job creation (user ruling; a backtracking regex ran for 85 s on a 36-character string, J8 in the plan). A safe regex engine may come later. `$toMillis` with a picture builds a regex too, so it fails at evaluation (final review fixes). Work inside one built-in call or operator is bounded by an allowlist of built-ins, caps inside a few of them, and steps weighted by the size of what nodes read and produce (see Final review fixes).

## Deviations from the plan

- `$shuffle` is also rejected, alongside `$now`, `$millis` and `$random` (ruling in Task 1: it uses `Math.random`, so it breaks determinism). Spec and constraints were updated; Task 1 fix round added the test.
- Banned names are rejected on any reference, not only calls (`$map(a, $random)` would bypass a calls-only check). A lambda parameter named `$now`, `$random` or `$millis` is therefore rejected too (a test pins it); the user renames it.
- "Templates cannot define `$` variables or functions" means template-supplied bindings; `:=` and lambdas inside an expression are allowed (the runaway-expression tests rely on it).
- Task 2 replaced all 17 occurrences of `applyTemplate(` (plan said 16 calls); Task 3's `getJob` edit used surrounding context because `return job;` is not unique. No effect on behaviour.
- The jobs test "does not run expressions" was renamed to say what it asserts (creation succeeds without evaluating against the sample).
- One extra record-level test: a non-step limit (sequence or depth) also yields `expr_limit`.
- `sources/sample` accepts `source.filter` and ignores it (samples show raw records), so a user may expect a filtered sample.
- Unused `CompiledExpression.text` was dropped.
- Test totals run 5 over the plan: unit 27 files / 486 tests.
- The `test:cf` run took 18 m 37 s, a little over the plan's 15 minute estimate; this machine's 10,000-row case is slower.

## Final review fixes

- `$toMillis` with a picture string fails with `expr_error` ("$toMillis with a picture is not available in templates; use the date field's format option"). JSONata builds a regular expression from the picture and runs it on the value (16 `[f]` on a 38-character value took 107 s), and the picture can come from the record, so the check runs at evaluation. The one-argument ISO 8601 form delegates to JSONata. No other built-in builds a `RegExp` from caller or record text.
- Steps are weighted by result size through JSONata's `__evaluate_exit` hook: an array result adds its length and a string result its length in KiB (rounded up) to the per-evaluation count, so the review's loops (`$sum([1..100000])` and `$map([1..100000], $string)` inside `$map`) end as `expr_limit` in milliseconds without a clock. A range literal is charged twice (the range and its array constructor), so `[1..40000]` fits and `[1..50000]` is over the limit.
- `$pad` is capped at a width of 10,000 characters (`expr_error` past it), and a fill string longer than the padding needs is cut before JSONata repeats it.
- The spec's example filter reads `$number(price) > 0` (XML values are text), and its Safety section describes the three changes above.
- The workerd runaway test also runs a built-in-amplified loop, which only the weighted count can stop.
- (Fixed in the allowlist round below.) The re-review found work still uncharged: `$clone` and the transform operator, deep `=` between large objects, `$distinct` over objects, the default `$sort`, `$fromMillis` width modifiers (1.65 GB from a 40-character literal), and per-character arrays in `$length` and `$substring` (308 MB).
- Test totals: unit 27 files / 496 tests (10 new); Node integration `selection.test.ts` 5 passed; workerd `-t runaway` 1 passed.

### Allowlist round (user decision)

- Templates may call only an allowlist of 45 JSONata built-ins (listed in the spec's Safety section). Any reference to another built-in fails job creation with `invalid_template` ("$sort is not available in templates"; several names sorted and joined), wherever it appears. `$eval` is now rejected this way instead of failing at evaluation. `$now`, `$millis`, `$random` and `$shuffle` keep their determinism message. A unit test reads `jsonata.js` and checks that the code knows every built-in it binds, so an upgrade that adds one fails the test instead of allowing it.
- Allowed built-ins may only be called directly (`$f(x)`, `x ~> $f()`, `items.$f()`). Passing one as a value, partially applying it, binding it to a variable, or naming a variable or parameter after it fails job creation. Ruling made in this round, beyond the brief: a built-in handed to `$map`/`$reduce` or partially applied with a large argument fixed runs once per element natively with no node charged (`$reduce(xs, $append)` is quadratic; `$map(range, $substring(s4MiB, ?))` scans 4 MiB per element). Two runaway tests that passed `$string` to `$map` now use a lambda (unit) or `$sum([1..100000])` (workerd).
- The transform operator `|…|` and the wildcards `*` and `**` fail job creation. `*` was not in the brief: it concatenates arrays quadratically (7.4 s on a record with 100,000 array-valued keys, within the count).
- Re-review follow-up (controller ruling): grouping a sequence (`expr{…}`, any node carrying a `group`) and the `@`/`#` bindings fail job creation. `evaluateGroupExpression` adds each member by concatenating the group's whole array, and `reduceTupleStream` repeats it per binding (`a#$i@$x{'': 1}` on 48,000 members 6.7 s; `[1..30000]#$i@$x{'': 1}` 2.2 s and 121 MB on any record). The object constructor on its own (`{"a": price}`, a `unary` node with no `group`) stays; because it groups an array context the same way (`n.{'': 1}` with a 48,000-member inner array took 1.6 s), it is charged `n²/1024` steps on entry for an `n`-member array context, which ends that case at once.
- Step weighting: one step per 256 bytes (was 1 KiB) of a string, an array's contents or an object (approximate deep size, cached per object in a `WeakMap`), plus an array's length. Changed from 1 KiB because at 1 KiB one `$join` built a 91 million character string (96 MB RSS) within the count; at 256 bytes an evaluation builds at most about 25 million characters. Built-in calls that read the context value (`$keys()` in a lambda) and field names looked up on an array are charged for that value on entry, because the record itself is not any node's result.
- Caps: `$fromMillis` pictures at 256 characters and widths at 64 (scanned without a regex); `$string` with indentation fails (quadratic in nesting depth); `$length` and `$substring` reimplemented on code points without a per-character array (results compared with JSONata's over a grid of strings and bounds); `$replace`, `$split` and `$join` count their result first and end as `expr_limit` before building past the remaining steps; `$replace` with a string pattern joins pieces once instead of appending per match; `$contains`, `$replace` and `$split` take string patterns only.
- Re-review follow-up (controller ruling): a record nesting arrays more than 32 levels deep fails each expression as `expr_limit` ("The record nests arrays more than 32 levels deep") before evaluation. JSONata's field lookup recurses and copies at every array level natively (99,999 leaves under 997 levels: `a.k` 1.82 s, `$lookup(a, 'k')` 1.85 s and 99 MB; the reader allows 1,000). The depth is computed once per record (iterative walk, `WeakMap` cache); the 997-level record is now rejected in 11–24 ms. Arrays built by the expression are charged per level, since each wrap reads the array built so far: `$reduce([1..n], function($a, $v) { [[$a]] }, …)` reaches about 900 levels with one leaf before `expr_limit`, and lookup loops over such arrays end as `expr_limit` within 52 ms.
- The bound is per evaluation: one record runs its filter, key, slug and every field expression separately, so a record can cost that many times the worst case below.
- Worst bounded case found (Node 22, no clock, records up to about 5 MB), re-measured after the group-by and depth fixes: a loop of `$pad('', 10000)` at 304–324 ms; `$replace` loops at about 210–240 ms; `$encodeUrlComponent` loops at about 180–200 ms; `$string` of a 2,000-deep nested array in a loop 177 ms; the tail-recursive runaway at 40 ms; object constructor over a 48,000-member array context under 40 ms; a record holding a million empty arrays read in a loop 189 ms (including its one depth walk); lookup over 32-level arrays with 99,999 leaves 92 ms.
- Test totals: unit 27 files / 603 tests (107 new or changed in `expressions.test.ts`); Node integration 7 files / 34 tests (369 s, before the group-by and depth follow-ups; `selection.test.ts` 5 passed after each); workerd `-t runaway` 1 passed after each.
