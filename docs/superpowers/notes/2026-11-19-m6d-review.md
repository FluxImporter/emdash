Process CPU on Node counts V8's compiler and GC threads too, which is why it exceeds the wall time
on a first call. On workerd the type checks account for about 100-160 ms of a request that takes
9-10 ms without them; that time is CPU, since nothing between the route's start and end waits on
I/O but the same 3-5 D1 reads the unmatched request makes. **At 200 keys both runtimes are an
order of magnitude over the free plan's 10 ms; at the real bound of 1,000 keys Node spends about
0.5 s of CPU in a warm process and 0.7 s in a fresh one**, about 0.5 ms per field-like key, fifty
to seventy times 10 ms. Workerd was not measured at 1,000 keys (the fix wave ran no workerd
suite); at 200 keys it tracked Node's later calls, so about 0.5 s is the expectation there too.
Without the cap a 10,000-key CSV would have cost about 5 s; with it, 10,000 keys cost the same
as 1,000. The free-plan note in the spec's open issues states these figures (Rulings 99, 100). A typical request is far cheaper: the products fixture's name matching takes 13-21 ms
of route time on workerd, D1 reads included. The SDK's first evaluation (V2) is the other free-plan
cost: 74-105 ms of CPU on Node, and 0.0-4.6 ms of startup CPU on workerd behind `await import()`
(Task 0), with the first in-request import not measurable on a production build here.

## Rulings

From the ledger (`.superpowers/sdd/2026-11-19-flux-import-m6d-ai-mapping/progress.md`), the
pre-flight scan and the task reviews. Spec Rulings 72-99 ("Amendments from the plan and review")

### Plan Rulings 1-22, and what the code does now

1. **`guardedRequest` reads the reply to its end under the cap before it resolves**
   (`src/sources/net.ts`): chunks are counted, the stream is cancelled with `TOO_LARGE` past
   256 KiB, and a new `Response` carries the bytes, the status, status text and headers minus
   `content-encoding` and `content-length`; opaque and status-0 replies are `FETCH_FAILED`
   (spec Ruling 72).
2. **The key travels as `authorization: Bearer`.** Tests on Node and workerd assert it and the
   absence of `x-api-key`; `redirect: "manual"` is forced inside the guard (spec Ruling 73).
3. **Errors map by `instanceof` and `status`** in the ruling's order (`aiErrorCode`,
   `src/plugin/ai/provider.ts`); the SDK adapter re-throws guard failures code-only through
   `guardFailure`, and a renamed-class unit test pins `instanceof` (spec Ruling 74).
4. **The span test is replaced** by the client-options pin and the `traceparent` check (spec
   Ruling 75).
5. **The caller passes `timeoutMs`**: the route passes `aiTimeoutMs(fieldsSent)`; tests read
   `x-stainless-timeout` (26 and 80 for 10 and 100 fields) (spec Ruling 97).
6. **`sourceId` samples the stored copy, else fetches with `force` set to whether a `lastFetch`
   exists**; `SOURCE_NOT_FOUND` is read by the route first, and a fetch's `NOT_FOUND` maps to it
   (spec Ruling 76).
7. **CSV keys keep `column_<n>`** (spec Ruling 77).
8. **`ignoreCase: true` follows from the values** for `select` and `multiSelect` (spec Ruling 78).
9. **A base template's key, slug and fields are kept whole**; its slug is never dropped (spec
   Ruling 79).
10. **The code layout** is the ruling's: `src/plugin/ai/` (`payload.ts`, `reply.ts`,
    `provider.ts`, `anthropic.ts`, `openai-compatible.ts`, `settings.ts`, `rate-limit.ts`,
    `merge.ts`), `src/engine/suggest.ts` (pure), `src/plugin/suggest.ts`,
    `src/plugin/overviews.ts`; the tool inputs live in `routes.ts`.
11. **`fields_not_sent` has `count` and up to 20 slugs, `keys_not_sent` only `count`** (spec
    Ruling 86).
12. **Rationales are `cut(text, 199)` plus `…`** (`src/plugin/ai/reply.ts:146`; spec Ruling 87).
13. **The workerd harness writes `.dev.vars`**, now with a marker line, mode 0600, and the
    developer's file renamed into `.wrangler/` for the run (spec Ruling 95).
14. **`ai_url_blocked` is proven on the shared server** with an OpenAI-compatible private base URL
    (spec Ruling 96).
15. **The M6c consent snapshot is derived** from the regenerated fixture (spec Ruling 98).
16. **`sample_trimmed` only for a payload that was sent** (spec Ruling 88).
17. **The provider's `key` and `slug` carry 0.6 and "Suggested by the model"**
    (`PROVIDER_KEY_HUNDREDTHS`, `src/plugin/ai/merge.ts`; spec Ruling 82).
18. **`unmapped.keys` leaves out the key column and the slug's key** (spec Ruling 89).
19. **A duplicate-key item keeps its field with `from: null`**, and a field is answered by its
    first item (spec Ruling 85).
20. **Base keys are `templatePaths` outside `key` and `source`** (after the Task 9 review: a
    select `map` entry is not a key), and **pasted text goes through `pasteBytes` and an
    in-memory `SourcePort`**; `SuggestDeps` has no storage port (spec Ruling 80).
21. **The keys sent** drop the base template's and the settled fields' keys, always keep the key
    column, and keep the slug's key (spec Ruling 90).
22. **Provider text is checked before it reaches a reply or a log**, and settings warnings need a
    call to be due; for Anthropic `aiBaseUrl` is read only under `allowPrivateNetwork` (spec
    Ruling 91).

### The final review's fix wave

The final whole-branch review found nothing Critical and one Important issue; the coordinator's
rulings were fixed on top of `de1ce90`, test first, in one code commit and one docs commit:

- **Name matching reads only the first 1,000 keys** (Important; spec Ruling 100).
  `suggestByName` scored every sample key, while `MAX_KEYS_SENT` (200) capped only the payload,
  so a CSV of field-like headers cost about 0.5 ms of CPU per key. `matchedKeys(sample)` is now
  the first `PATHS_MAX_COUNT` (1,000) keys in sample order; the field pairs, the key column and
  the slug are chosen among them, and the rest are counted in a new count-only warning,
  `keys_not_matched`, after `sample_empty`. The route sends the provider only keys from the
  same prefix, so `keysSent` stays a subset of the matched keys (before, a key past the 1,000th
  could be sent whenever more than 800 of the first were excluded or too long);
  `unmapped.keys` still lists keys past the cap, bounded at 100. Measured above (V5).
- **`sample_trimmed` only for a payload that was sent** (spec Ruling 88, refined). The route
  added it as soon as the payload was built, so `ai_rate_limited` (a used-up hour or a KV error)
  and `ai_url_blocked` replies reported a trimmed payload with `sent: null`. It now waits for a
  non-null `sent`; `keys_not_sent` and `fields_not_sent` are still reported once the payload is
  built, as for a payload too large.
- **`ai: false` survives a settings read failure.** A failed `aiProvider` read now reports
  `ai: { available: false }` and the route answers by name; with `ai: true` it is still a 500,
  an accepted open issue now in the spec.
- **Docs.** Ruling 64's `sent` is set once the provider call is attempted (spec Ruling 101; no
  code change). Rulings 68 and 99 corrected to the 1,000-key bound and its measured cost. The
  spec's free-plan CPU open issue states the measured cost; the `readAiSettings` rethrow is a
  spec open issue. Markers added at every passage amendments 72-101 change (the Decisions and
  "The transport" text now point to Ruling 72, the settings warning to Ruling 91, "Validating a
  reply" to Rulings 81, 84, 85 and 87, among others). The roadmap row now says a source's copy
  is fetched when it has none or it is gone, and gives the new CPU figure.
- **Checks.** `pnpm format`, `typecheck`, `lint` and `test` pass (104 files, 2,821 tests).
  Twelve mutants of the three code fixes were all killed. The integration and workerd suites
  were not rerun: their assertions on warnings use `toContain` or `arrayContaining`, none sends
  more than 1,000 keys, a trimmed payload or a failing `aiProvider` read, so none should change.

## Open issues

New in this review (added to the spec's "Open issues" where they concern the design):

- **The free plan's CPU: settled, it is exceeded** (spec Rulings 68, 99 and 100; the spec's open
  issue now says so). Name matching at its bound (1,000 keys that each name-match a `datetime`
  field, 20 date-like values each) costs about 0.5 s of CPU on Node in a warm process and 0.7 s
  in a fresh one; at 200 such keys, 110-290 ms on Node and 100-160 ms of route time on workerd
  (V5 above). That is ten to seventy times the free plan's 10 ms. A typical feed costs far less
  (the products fixture's whole route: 13-21 ms on workerd, D1 reads included), but a wide feed
  of date-like columns whose names resemble the collection's date fields passes 10 ms. Imports
  need the paid plan anyway (M6c); on the free plan an Admin should use `ai: false` with small,
  narrow samples. M8 documents it. A cheaper check (stop a candidate at its first failure once
  another reads every value) is a later option.
- **Ruling 58's mark stripping merges more than accents** (Task 3 review): NFKD with combining
  marks removed also folds Devanagari vowel signs (`कीमत` = `कमत`) and Japanese voicing marks
  (`ガス` = `カス`), and such pairs settle at 1.0, so they are not even sent to a provider. The
  Admin reviews the draft; a fix would strip only Latin-script marks.
- **SDK 1.5.0 warns on the console for a deprecated model** (Task 6 review): `console.warn` from
  inside `beta.messages.create()` for `claude-sonnet-4-5` and its dated ID, ignoring `logLevel`.
  No secret is printed; the model reaches end of life on 30 November 2026, after which the
  warning cannot fire for it. No code change.
- **A storage failure while reading the key is a 500** (Task 7, accepted; Task 9 review; spec
  Open issues since the final review): `readAiSettings` maps encryption errors to
  `ai_key_unavailable` but re-throws any other settings read error, so a failing settings read on
  the `ai: true` path is a route error, not a fallback. Accepted, since plugin storage failing
  breaks the rest of the request anyway. The `ai: false` path is guarded by the fix wave: a
  failed `aiProvider` read reports `ai: { available: false }`.
- **`ai_rate_limited` covers a KV failure too** (spec Ruling 92): a client cannot tell a used-up
  hour from a storage error; the log's `rate=kv_error` can.
- **`network:request:unrestricted` also lets the plugin's admin pages load images from any host**
  (pre-flight F14). It is declared for disclosure (spec Rulings 42, 49); M7 should keep that in
  mind for any image it shows from a feed.
- **The workerd test cannot read the site's log** (Task 11, accepted): Task 10's third safety
  step (the call-free probe that logs `host=127.0.0.1` for Anthropic) exists on Node only. A site
  ignoring Anthropic's `aiBaseUrl` under `allowPrivateNetwork` is caught by Task 10's guard and the
  settings unit test.
- **Base keys outside field mappings and the slug are not reserved in the merge** (Task 8): keys a
  base template reads in taxonomies, bylines, `alt`, `translationOf` or `publishAt` are never
  sent, so `validateReply` drops a reply item naming one as an unknown key. Harmless today.
- **The SDK's first import on a fresh `sites/dev-cf` dev server** reloads the worker when Vite's
  dependency cache is cold (the route took 919 ms; 424 ms on a warm cache, 41-44 ms after). A
  dev-only effect, but a test that keeps in-memory state across that first call loses it (V5).
- **The production build still cannot run** (the M2 blocker, carried forward): `astro build` of
  `sites/dev-cf` succeeds, but the built worker answers 500 with `TypeError: Class extends value
  undefined is not a constructor or null` (V2 above). So the SDK chunk's lazy loading and its
  first-call cost in a production worker are unverified, as is everything else on a build.
- **The record-rules crash-and-resume "flake" is settled: the test, not the engine** (M6c note,
  Open issues). It recurred here: "schedules every entry once when a crash cuts the job off
  mid-batch" ended `created: 299, conflict: 1` in the full Node run, alone, and in one of two
  further runs, with WSL stable. Database snapshots taken after the kill showed the cause. The
  kill landed after `content.create` and before the engine saved that create's `writtenRev`: the
  record was `writing` with no entry ID, the journal row unconfirmed, no link, and the entry an
  unscheduled draft. On resume, crash repair finds the entry, but nothing proves it is the job's,
  so the row is `conflict`, `schedule_unverified`, and the draft stays unscheduled. That is the
  M5b design (M5b spec "Crash repair": the window ends in `schedule_unverified`, as
  `publish_unverified` does). The test had assumed only the later window, between the schedule
  call and the link put (M5b plan Ruling 12). The WSL clock step (F1) was ruled out: it occurred
  in passing and failing runs alike, and the failing path compares no times. `batch.ts` has not
  changed since M5c, so this is not a regression. The fix is tests only: the integration test now
  takes `crash.test.ts`'s criterion (every conflict is `schedule_unverified`; exactly those
  entries stay drafts; 300 entries with 300 distinct keys, so nothing is dropped or doubled), and
  a unit test in `schedule.test.ts` reproduces the window deterministically. The fixed test passed
  12 of 12 runs, one of which landed in the window. Proving the window, so the draft could be
  scheduled, would need the entry ID that only the lost response carries; that stays a design
  limit.
- **Known flakes.** F3: `Cursor.exe` still holds ports 4392 and 4397, so `translations.test.ts` and
  `retention.test.ts` fail in setup in every full Node run, and pass alone on free ports. F1, the
  WSL clock step: seen during this review's runs (+1.5 s, then −3.8 s around a server restart),
  with no test failing because of it. Load: a `test:cf` run that shared the machine with twelve
  Node integration runs lost its 10,000-row test to the 1,800 s timeout, and three later tests
  failed as fallout (two `SQLITE_BUSY` from the test's own `wrangler d1 execute`, one HTML error
  page from the busy server); see Checks.
- **The 10,000-row workerd test is close to its timeout.** With nothing else running it took
  1,490.8 s of its 1,800 s `testTimeout` (83 %; M6b measured 1,365.0 s alone, and the config
  comment's 870 s is out of date). Under load it timed out and took three later tests with it.
  Raise its own timeout, or cut its rows, before the suite grows again (carried to M7).
