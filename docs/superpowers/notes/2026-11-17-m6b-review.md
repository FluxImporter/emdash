### V5 on the final code (Step 2)

**How.** A temporary `sites/dev-cf/src/pages/test/d1-count.ts` (dev only, CSRF header): on `start`
it wraps `prepare` on the prototypes of `env.DB` (`cloudflare:workers`) and of its `withSession`
object, as M5a's `countD1`; on `stop` it restores them and answers the count. Three `start`-`stop`
pairs with nothing between them counted 0 (no D1 statement after the wrap in the counter's own
requests; M6c's PAT-authenticated probe route counted 4), so nothing is subtracted. The driver was
a temporary vitest file run against `sites/dev-cf` started by hand on a fresh local D1 (port 4396),
with the dev-bypass PAT in process memory only. Before each event it set `next_run_at` with
`wrangler d1 execute` so that exactly the named flux-import tasks were due (the others pushed to
2099), then sent one `GET /cdn-cgi/handler/scheduled?cron=*+*+*+*+*` between `start` and `stop`,
with 1 s of settling before `stop`. Every count is the whole event: EmDash's claim, finish updates,
recovery, publishing sweep and heartbeat included. Wall time is the event's HTTP round trip.

**The worst event's state.** Eight schedules on one template and source; a linked schedule whose
update job was mid-run (12 posts of the M4b links schema, each changing title, `author` reference,

### Plan Rulings 1-20, and what the code does now

1. **The stop-timer route lives in the test sites.** `sites/dev` and `sites/dev-cf` have identical
   `src/pages/test/stop-cron-timer.ts` files: 403 unless DEV, 403 without the CSRF header, then
   `runtime.stopCron()`. Both integration tests check the 403 without the header (spec Ruling 60).
2. **The busy check filters dry runs in code.** `busyJob` pages `{ feedSourceId, status: in
   unfinished }` 20 at a time on the `["feedSourceId", "status"]` index, skips dry runs, and stops
   after `BUSY_SCAN_PAGES` (5), failing closed (spec Ruling 54; Open issues).
3. **flux-import checks each cron field.** `cron-syntax.ts`'s grammar, stricter than the plan: it
   also refuses days no listed month has (Task 2), so the brief's acceptance of `0 3 31 2 *` (as
   EmDash's refusal case) was reversed. 118,584 expressions were probed through EmDash's own
   validator and 55,747 day/month forms re-probed after the review: no accepted expression becomes
   a one-shot or overflows (spec Ruling 55).
4. **The held-lease test reads the lease from the pump's own query**; any other job gets
   `nextBatch`, which is the tick's unit (spec Ruling 61).
5. **`schedules/update` schedules before it writes**, and re-synchronises the task from the newest
   row on any later failure (Task 2 review; spec Ruling 62).
6. **A disabled schedule is never due** (spec Ruling 63); `pump.test.ts` "ignores a disabled
   schedule's due mark".
7. **A launch claim makes the routes busy** (spec Ruling 64).
8. **No engine change for the empty feed**: finalization reads `(missing?.fromSeq ?? cursor.seq) ===
   0` (spec Ruling 53).
9. **`services.ts`** holds `buildServices`, `withScheduledServices` and `createJobFrom`;
   `ensureRetentionScheduled` and the shared `syncRetentionTask` live in `retention.ts` (spec
   Ruling 67).
10. **`jobs/next` reads the job first** (one more `get`), then builds the null-actor services for a
    scheduled job (spec Ruling 68).
11. **A resumed or retried finalized scheduled job reopens**, and `jobs/resume|retry` answer with
    the reopened row (preflight F19); only `origin: "schedule"` jobs try the reopen (spec Ruling 65).
12. **Finalization repeats a rollback's pause**, only while the row is not newer than the job
    (preflight F10) and only when the rollback came first (F20) (spec Ruling 66).
13. **The key check is the template's shape check** (spec Ruling 69).
14. **`sources/update` adds `warnings` only when there are some** (spec Ruling 70).
15. **Strict schedule inputs**, plus a 16 KiB body cap and the schedule name wording (spec Ruling 71).
16. **Retention meters each storage call**, deleting in pages of 50 so each call is one D1
    statement (Task 6 review; spec Ruling 72). V5: 150 metered calls cost 156 queries with the hook.
17. **`scheduler.ts` dispatches the hook; activation reconciles** without the runtime (F5) and never
    throws (Task 7 ruling) (spec Ruling 73).
18. **Deterministic ticks after the acceptance** on Node (`stopCronTimer`, then `tick`), events only
    on workerd (spec Ruling 75).
19. **The creator check compares with `Permissions["import:execute"]`**; no `ctx.users` or a
    non-numeric role pauses `creator_gone` (spec Ruling 76).
20. **A crashed launch's claim is replaced once its job finished**; a claim whose job is
    unfinished stays in flight however old (Task 4 review added the test) (spec Ruling 77).
